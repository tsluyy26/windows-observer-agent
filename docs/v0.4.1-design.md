## 边界与方案

保留 Scene、Prompt Builder、Plan Parser、Validator 和规则回退，不改 MCP 观察流程。
新增 providers.py（统一配置/能力/请求/响应/注册及管理）、provider_adapters.py（SDK适配）。
旧 llm_provider.py 的 Mock/OpenAI 类保留 generate/generate_async 兼容，内部走统一接口。
Planner 调用 complete(LLMRequest) 并只消费 LLMResponse，不导入厂商 SDK。
旧第三方 generate 接口仅经显式兼容包装转为 LLMResponse，不能把原始 SDK 对象送进 Parser。

ProviderConfig 为明确的单模型配置；ModelCapabilities 全部逐配置声明，不按厂商猜测。
图像/工具/流式能力可记录，但本轮请求一律禁止启用这些功能。请求支持 structured_output、
json_mode 或纯文本 JSON，始终进行现有本地校验。Adapter 不自动降级接口或切换服务。

TOML 支持多个命名 Provider。Registry 只注册代码中的 factory，配置不能 import Python。
Manager 可显式选择 Provider；更换同配置模型必须同步提供能力声明，或选择另一命名配置。
选择及配置验证是纯本地操作，不创建 SDK/事件循环/网络。外部调用另需运行时授权和环境密钥。

HTTPS 默认允许作为配置；只有官方 OpenAI 默认端点免自定义地址确认，其他端点须逐地址确认。
HTTP 仅字面量 localhost/127.0.0.1 且运行时显式授权；不接受用户信息/query/fragment、
0.0.0.0、替代 loopback 写法或网络协议。TLS verify=True、禁代理/重定向/自动重试，
请求前再次校验完整端点/方法，资源由上下文关闭。额外参数不能覆盖认证、端点、工具或安全设置。
密钥只读取环境变量，不复制到配置/请求数据、repr 或日志。真实 Provider 默认关闭。

## 实施结果

统一类型及管理位于 providers.py；SDK Adapter 位于 provider_adapters.py。Registry 注册
受信 Python factory，默认只有 mock/openai_responses/openai_chat_completions；没有从 TOML
动态导入代码的功能。ProviderManager 显式 select，每个模型配置各自声明能力，更换模型时
不能静默复用旧能力。外部 factory 运行前验证授权、共享、地址确认和环境密钥；无自动服务切换。

OpenAI SDK 保持 3.42.0，实际检查了 AsyncOpenAI 与 AsyncCompletions.create 签名；
底层为 httpx2 2.16.0，没有升级或新增第三方依赖。Responses 使用 text.format，Chat 使用
response_format/messages 与标准 max_tokens。统一 LLMResponse 的 model 是请求配置模型，
不证明服务端实际模型身份；只有文本、完成状态与安全 token 计数进入后续规划。
结构化、JSON mode、纯文本 JSON 按配置选择，不在错误时自动更换格式或接口。

配置字段 extra_params 传给 SDK extra_body，递归拒绝认证、消息、模型、输出预算/格式、
工具、托管 prompt/access_programs、TLS 等保留字段。密钥不能出现在配置元数据/额外参数、
请求正文或输出文本中；异常只使用固定原因码。保留 v0.4 OpenAI.generate/generate_async
和 Mock.generate API；Planner 仅调用统一 complete（旧 generate 通过兼容包装）。

本轮自审及独立代码审查修正：

- built-in SDK 配置缺地址时即配置验证失败，不留到请求阶段。
- 服务端回显密钥或自定义 Adapter 输出密钥时拒绝，第三方异常不向用户输出原文。
- SDK/Manager 共用带锁引用计数日志抑制，嵌套或重叠调用最后退出时才恢复日志。
  原 snapshot/restore 在 A 先退出而 B 仍运行时会提前开启日志；先复现失败再修正。
- LLMRequest 深拷贝 data/schema，Manager 再隔离 Adapter 请求，避免扩展代码意外改写
  本地证据校验依据；用合成 C999/E999 伪造回归验证必须拒绝。
