# v0.4 LLM Planner：审查、设计与验收

日期：2026-11-01。基线实跑 83 项测试通过；本轮不做真实 MCP 或模型联调。

## 审查与选择

Scene 已保留控件来源、未知值、控制状态、时间和原始数据，可复用，无需改观察通信层。
Plan 目前将控制权不足与规划失败混在 status=blocked 中；将增加独立 planning_status，
所有计划仍 executable=false。为保持原接口，make_plan 默认保留旧门控语义；CLI 改用
review_only=True 的审查规划语义，允许 ready/user 状态下规划，不改变 Live 的观察门控。
原有 83 项测试保留，再新增明确测试两种接口语义。缺失或失败观察仍不能推断具体界面步骤。

选择三个小模块：planning_input 负责数据最小化及 Prompt；llm_provider 定义同步 Mock 和
异步官方 SDK Provider；llm_planner 负责严格解析、证据引用和本地校验、超时及规则回退。
不采用 Agent 框架或工具调用循环；不提供执行器或任意 URL 的模型端点。
真实 Provider 仅支持明确指定模型的 OpenAI 官方 HTTPS Responses API；可选依赖锁定，
核查安装 API 后用内存 HTTP 测试，绝不调用付费接口。默认规则模式不导入 SDK/事件循环。

## 输入与安全边界

不向模型传 Scene.raw、原图、标题、路径、自由控件文本、原始来源字符串和错误文本。
为窗口/控件/证据生成本次局部别名；仅保留有限应用/控件类型、已知通用入口语义及布尔属性。
目标也脱敏路径、邮箱、凭据；过度脱敏时明确需确认。所有 UI 文本视为不可信，使用白名单
语义与 JSON 数据区；可信系统指令和目标/观察资料分离。不承诺提示词能消除全部注入风险。

模型输出只能是带固定 operation 枚举的审查计划，必须有理解、步骤、条件、元素引用、验证、
停止条件、未知项与确认事项。引用必须来自本次提交的 alias/evidence，额外字段、重复 JSON
键、危险操作/文本、伪造元素均拒绝。无工具定义；输出永不进入任何执行通道。
外部请求须 planner=openai + 显式数据共享确认 + 环境密钥 + 显式模型；否则请求前拒绝。
外部失败只报告固定原因码，不输出原始异常/正文；有界超时、禁重试、禁代理/重定向并关闭资源。

## 实施与验收顺序

1. 先编写新测试并确认缺失实现失败；添加规划状态和安全输入投影。
2. 实现 Mock Provider、严格计划解析/校验及规则回退；保留默认离线路径。
3. 安装锁定可选 SDK并核实签名；通过内存 HTTP 验证请求格式、认证、错误、超时和关闭。
4. CLI/Reporter 展示规划状态、来源、回退原因、确认项；Live 先关闭 MCP 再规划。
5. 跑全套测试、CLI Mock/Replay/Mock LLM 和编译检查，更新文档与项目状态。

验收以用户十四类新增场景、原 83 项测试及无真实网络/进程启动为准。

## 实际 SDK 核查与修正

可选依赖安装并锁定 openai==3.42.0（新增 jiter、sniffio），不升级 mcp/httpx2。
检查本项目 .venv 安装包签名及源码：AsyncOpenAI 注入 httpx2.AsyncClient，
responses.create 支持 instructions/input/text/tools/tool_choice/store/stream/max_output_tokens，
response.output_text 只聚合 message 中的 output_text。不照搬其他主版本的 httpx 示例。
官方参考（2026-11-01 读取）：
[Responses](https://developers.openai.com/api/reference/python/resources/responses/methods/create)、
[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)。

SDK 构造时会检查 httpx2 client 类型，测试替身使用真实类的子类注入 MockTransport，
没有 monkeypatch 成普通函数；否则会产生测试替身本身的 TypeError，不能当作接口故障。
允许并忽略 reasoning 输出元数据，必须实际存在 message/output_text，拒绝函数工具等输出。
禁用自动重试及环境代理，显式固定官方端点；request hook 再检查路径/方法，拒绝重定向。
固定原因码和 logging 禁用/恢复避免第三方请求/异常正文进入报告或日志。

## 审查发现及回归

- 目标缩减不能把否定命令变肯定：含否定或动作/对象不足时标记需确认，只接受 ask_user。
- 元数据明确不完整时不能推断完整；UI 截断和输入预算截断独立保留。
- 公开控制状态不能原样复制未知 state/generation/wait；只保留有限状态枚举。
- 控件/证据必须一一匹配，文字中提及的 W/C 别名也须已引用；失败观察不接受具体动作。
- 独立只读审查复现未保存文档关闭/运行 exe/宣称完成被接受的问题，已补保守拒绝及测试。
  词法检查仍有语义局限，不构成任务正确性证明；本程序无执行路径是最终边界。
- 独立审查复现合法 reasoning 被拒绝的问题，已用真实 SDK + 内存 HTTP 回归修正。
