## 设计决策

1. 固定可选依赖 mcp==2.3.0、httpx2==2.16.0 并生成 uv.lock。依据本机同版本源码，
   使用显式 streamable_http_client(http_client=...) + ClientSession.initialize()；
   SDK 2.3 的 streams 是两个成员，list_tools 使用 params=PaginatedRequestParams。
   不套用 SDK 1.x 的 httpx、三元组或不同函数名。
2. `--live --endpoint http://127.0.0.1:<port>/mcp` 显式开启；无 --live 时不读取 Token、
   不导入 SDK、不创建事件循环。端点只接受字面量 127.0.0.1，无凭据/query/fragment。
3. Bearer Token 仅从 WOA_MCP_TOKEN 环境变量读取；不提供 Token 构造参数或 CLI 参数。
   私有 HTTP client 使用 trust_env=False，禁用代理与重定向；逐请求再次校验目的地址。
   不启用网络/SDK日志，不将第三方原始异常或服务日志转发给终端。
4. Live 流程：initialize → 分页 list_tools（有页数/游标限制）→ ControlStatus →
   Screenshot → Snapshot。额外工具只发现不调用；缺少三个必需工具时停止。
   Live 单独入口，不改变兼容的 v0.2 observe_mcp 默认顺序及 Replay 合约。
5. 根据本机 0.8.8 ControlToolGate，ready/ai 可尝试只读工具，user/pending/unavailable
   不调用截图/快照。服务可能为观察建立保护租约，这是服务自身逻辑；客户端不切换控制权。
   任意工具拒绝即停止，无自动重试；保留已有时间/来源并生成失败报告。
6. 只将 Screenshot 图像留在短暂内存，标准化后去除 data，记录 MIME/是否收到；
   报告明确依据 UI 树/文本，没有视觉分析。默认 Live 输出脱敏报告，避免正文进入日志；
   原始结果不写文件。Live 成功与 Planner 被阻塞分开判定，ready 的成功观察可返回 0。
7. PowerShell 联调脚本与 Agent 分离。只在用户退出 Codex 后手动运行；检查旧实例和端口，
   发现即中止，不终止原有进程。启动指定已安装 0.8.8 的 Python，使用随机临时 Token
   环境变量和固定本地安全配置，关闭服务遥测，保留控制保护，只开放三个工具。
   对本轮进程使用持有的 Process 对象和进程树清理，检测残留并给人工检查说明；
   不承诺对强制关闭 PowerShell/系统崩溃等情况的 finally 清理。

## 实施/验收顺序

- 检查版本 API 与 0.8.8 服务 CLI/认证配置，本轮不导入或启动服务包。
- 先增加 Live 测试，再扩展 transport、工具发现、观察流程及 CLI。
- 安装锁定的可选 SDK，在内存 HTTP transport 上验证真实 SDK initialize/list/call/close，
  不监听 TCP、不连接桌面服务；另用替身验证取消、拒绝和超时。
- 准备脚本并运行 PowerShell AST/安全替身测试，不调用实际服务启动流程。
- 运行全部测试、离线 CLI 和语法检查，更新 README/PROJECT_MEMORY。

真实 HTTP/真实桌面联调由用户关闭 Codex 后执行；本轮只验证代码和自动化测试。

## 验证结果与实际 API 修正

- 本项目实际安装 mcp 2.3.0/httpx2 2.16.0，并用 inspect 核实上述签名。
- 73 项自动化测试通过，其中原有 50 项保留；真实 SDK 合约测试使用 MockTransport，
  明确禁止实际 socket.connect；PowerShell 测试仅 dot-source 函数并替换系统查询。
- 真实 SDK 测试发现 AnyIO 网络故障先取消等待者，异常在退出后台 task group 时才出现；
  已修复连接/调用/上下文退出的安全异常转换，认证失败不会误报主动取消。
- SDK 将默认端口规范化，逐请求检查按 scheme/host/有效 port/path 比较，仍禁止跳转到其他目标。
- CLI 和脚本手工 Live 路径已经准备；没有运行真实服务启动流程，无法确认真实桌面联调结果。

## 隐藏 Agent 输出修正（2026-11-01）

用户后续手工执行已看到服务监听和清理成功，但只有 LIVE_TEST_STOPPED，没有报告。
发现 Invoke-TestAgent 隐藏启动 Python 时依赖控制台继承，未显式捕获 stdout/stderr。
新增 Invoke-AgentProcess 作为进程 I/O 边界：同时读取 UTF-8 管道、转发脱敏 stdout 和
CLI 安全错误提示、屏蔽 Token、不保存文件，且保证报告不会污染整数退出码。
Reporter 增加停止原因。新增合成 Python 子进程回归与停止原因测试，共 77 项通过。
合成子进程不启动 MCP；用户真实观察的停止原因仍需下一次可见报告确认，不推测或绕过保护。

## Screenshot 失败与大图 SSE 覆盖（2026-11-01）

用户可见报告显示 ready，失败发生于 Screenshot，原错误分类被 MCPClient 的通用捕获丢弃。
补查发现：服务默认 SSE，SDK 默认 1 MiB 单事件上限，而原真实 SDK 测试仅使用 JSON 小图。
新增大于 1 MiB 合成 base64 的 SSE 测试，在修改前复现 Screenshot 失败；采用明确的 16 MiB
上限后通过，保留有界限制。真实用户失败的根因仍需下一次诊断确认，不把模拟复现当现场证据。

新增 diagnose_tool_failure 和安全诊断字段，只输出允许分类/数字/控制错误码，不输出原文；
Reporter 显示已调用工具和诊断。失败的公开 Scene 保留原停止原因，Snapshot 未调用不再遮盖
Screenshot 错误。新增五项诊断测试和一项 SSE 测试，现共 83 项通过；未启动真实服务。
