## 改动前发现的问题

1. 模块责任划分合理，无需重构成复杂类层次；唯一 Protocol 是未来客户端边界，保留。
2. Observation 只保存 Mock 形状，缺少逐次工具时间、原始 MCP envelope、解析警告、
   字段来源与来源类型。新增带默认值字段，保持 v0.1 构造和测试兼容。
3. Planner/Reporter 固定声称 Mock，会误标真实回放。改为按来源显示，回放不代表实时状态。
4. ControlStatus 内部 owner 与真实 state 不同；只映射 ai→agent，ready 等仍阻塞，
   不把“可申请”当作已拥有控制权。畸形 error 对象也不能忽略为成功。
5. Mock 500 项规则不能直接用在真实结果。真实 UI 树用明确 truncated 文本，
   没有完整性证明时保守未知；保留解析警告和截断来源。
6. 缺少传输生命周期、连接/调用超时、JSON-RPC 错误、工具白名单与网络默认关闭机制。
7. 现有测试覆盖主要业务分支，但后台/未知目标混在一项，缺少首次导入安全测试、
   真实混合内容、错误文本、状态冲突、生命周期清理与脱敏边界测试。新增专门测试文件。
8. frozen dataclass 含可变 dict，已有文档说明；继续采集时深拷贝，不引入深冻结框架。

## 本轮设计

- 保留同步 `ObservationClient.collect()` 供 CLI 和 Mock 使用。
- 新增异步 `MCPClient` 管理 `connect/call_tool/close` 和 async context。
  传输遵守相同接口；所有操作有超时，无后台线程和不可取消的超时“包装”。
- ReplayTransport 只读脱敏记录；HTTP transport 默认拒绝连接，显式开启且指定
  已确认的 loopback 端点后才可使用；SDK 懒加载，无 stdio 实现或进程启动路径。
- HTTP 可选依赖不在本轮安装，实际网络分支不联调；使用内存传输验证超时、清理与白名单。
- 解析 MCP `content`/`structuredContent`/`isError`、JSON-RPC error、SDK snake_case，
  图像只保留 MIME/省略标记，不保留或打印 data。
- 文本解析以本机 0.8.8 renderer 为依据；不根据窗口标题推断 exe。
  不能唯一关联的 UI 控件保留为未归属控件，不强行挂到活动窗口。
- 回放记录区分真实脱敏与合成合约样本；只在 tests/fixtures 保存必要结构。
  清理后的文本只保留允许结构，标题、正文、值和未知行全部移除或替换。

## 实施结果与修正

- 已完成上述实现；详见 README 的当前目录和模块说明。
- 实测纠正：FastMCP 将无图 Snapshot 的 list[str] 序列化为文本块中的 JSON 数组，
  已增加 decode_text 和对应测试，而非仅按工具函数的 Python 返回类型推断 wire 格式。
- Windows 离线回放使用同步路径，避免 asyncio 的本地 socketpair；异步 ReplayTransport
  仅用于通信合约测试。新增测试首先复现失败，再移除 CLI 的事件循环使用。
- 首次样本未计时；最终重新采样记录了逐调用 UTC 请求与接收时间，明确不是服务捕获时间。
- 重新采样处于 user 状态，Snapshot/Screenshot 返回错误，最终 fixture 是真实错误回放，
  不伪装为成功观察。首次成功工具返回核实的格式继续由合约测试覆盖。
- 原有 17 项及新增 33 项测试通过，共 50 项；包括真实脱敏错误 fixture 的 CLI 回放。
- HTTP 仅默认关闭的可选 API；真实 SDK 未安装到项目、真实 HTTP 未联调，明确保留限制。
- 独立只读审查的两项问题已用失败测试复现并修复：非 ai 状态 generation 可能带对象，
  以及多文本块重置别名导致窗口身份错配。所有状态都校验 generation，映射提升到记录级。
- 采集端首轮 fixture 的句柄索引错误已更正；该 fixture 已由重新采样替代，不作为成功证据。
